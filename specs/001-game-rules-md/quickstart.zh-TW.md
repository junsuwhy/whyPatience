# 快速入門指南：桌面版接龍網頁應用程式

## 開發設置

### 前提條件

- 已安裝Node.js 18+
- npm或yarn套件管理器
- 現代瀏覽器（Chrome 90+、Firefox 88+、Safari 14+）

### 初始設置

```bash
# 克隆並設置專案
cd whyPatience
npm install

# 啟動開發伺服器
npm run dev

# 在瀏覽器中開啟 http://localhost:5173
```

### 專案結構

```
src/
├── components/          # React組件
│   ├── Card/           # 紙牌組件及變體
│   ├── TableauColumn/ # 牌列組件
│   ├── FoundationPile/ # 基礎堆組件
│   ├── StockPile/     # 抽牌堆組件
│   ├── GameBoard/     # 主要遊戲板
│   └── GameControls/  # 遊戲控制和UI
├── hooks/              # 自訂React hooks
├── services/           # 遊戲邏輯和存儲
├── types/              # TypeScript類型定義
├── utils/              # 輔助函數
└── styles/             # Styled-components和主題
```

## 核心用戶流程測試

### 流程1：新遊戲設置

**目標**：驗證初始遊戲狀態正確創建

**步驟**：

1. 在瀏覽器中開啟應用程式
2. 點擊「新遊戲」按鈕
3. 驗證遊戲板佈局：
   - 7個牌列分別有1-7張牌
   - 頂牌朝上，其他朝下
   - 4個空的基礎堆
   - 抽牌堆有剩餘紙牌
   - 遊戲計時器開始

**預期結果**：

- 總共52張牌正確分配
- 遊戲狀態顯示「進行中」
- 所有互動元素響應滑鼠懸停

### 流程2：基本紙牌移動

**目標**：測試拖放紙牌移動

**步驟**：

1. 開始新遊戲
2. 找到可放在黑色紙牌上的紅色紙牌
3. 將紅色紙牌拖到黑色紙牌上
4. 釋放以放下
5. 驗證移動已執行並記錄

**預期結果**：

- 紙牌移動到新位置
- 移動計數器增加
- 復原按鈕變為可用
- 紙牌位置正確更新

### 流程3：基礎堆建立

**目標**：測試建立基礎堆

**步驟**：

1. 開始新遊戲
2. 在牌列或抽牌堆中找到A牌
3. 將A牌拖到基礎區域
4. 找到對應的同花色2
5. 將2拖到A上

**預期結果**：

- 基礎堆以A開始
- 2成功放在A上
- 分數適當增加
- 視覺回饋顯示有效放置區域

### 流程4：抽牌堆操作

**目標**：測試抽牌堆抽牌模式

**步驟**：

1. 以1張抽牌模式開始新遊戲
2. 點擊抽牌堆抽牌
3. 如果可能使用已抽的牌
4. 在設定中切換到3張抽牌模式
5. 測試一次抽3張牌
6. 測試整個抽牌堆循環

**預期結果**：

- 根據選擇的模式抽牌
- 棄牌堆正確顯示已抽的牌
- 抽牌堆空時循環功能正常
- 抽牌模式在遊戲間保持

### 流程5：遊戲勝利

**目標**：測試勝利條件檢測

**步驟**：

1. 載入接近勝利的遊戲狀態（作弊/除錯模式）
2. 將最後的紙牌移到基礎堆
3. 驗證勝利條件觸發
4. 檢查勝利動畫和統計

**預期結果**：

- 遊戲立即檢測到完成
- 勝利訊息顯示
- 顯示最終統計（時間、移動次數、分數）
- 出現開始新遊戲選項

### 流程6：復原功能

**目標**：測試移動撤銷

**步驟**：

1. 開始新遊戲並執行幾次移動
2. 點擊復原按鈕
3. 驗證最後一次移動被撤銷
4. 測試連續多次復原
5. 驗證復原限制（如果實作）

**預期結果**：

- 紙牌回到之前的位置
- 移動計數器減少
- 遊戲狀態準確恢復
- 沒有可復原移動時復原按鈕禁用

### 流程7：本地存儲持久化

**目標**：測試遊戲狀態保存/載入

**步驟**：

1. 開始遊戲並執行幾次移動
2. 關閉瀏覽器分頁
3. 重新開啟應用程式
4. 驗證遊戲狀態恢復
5. 測試偏好設定持久化

**預期結果**：

- 確切的遊戲狀態恢復
- 所有紙牌位置保持
- 計時器從保存的狀態繼續
- 用戶偏好設定正確載入

### 流程8：無障礙導航

**目標**：測試鍵盤和螢幕閱讀器支援

**步驟**：

1. 啟動螢幕閱讀器載入遊戲
2. 僅使用Tab鍵導航
3. 使用Enter/Space與紙牌互動
4. 測試箭頭鍵進行紙牌選擇
5. 驗證ARIA標籤是否被朗讀

**預期結果**：

- 所有互動元素可通過鍵盤到達
- 螢幕閱讀器清楚朗讀紙牌狀態
- 焦點指示器清晰可見
- 鍵盤快捷鍵按預期工作

### 流程9：效能驗證

**目標**：測試動畫效能和響應性

**步驟**：

1. 開啟瀏覽器開發工具效能頁面
2. 開始效能記錄
3. 執行快速紙牌移動
4. 多次發新遊戲
5. 檢查動畫期間的幀率

**預期結果**：

- 動畫維持60fps
- 紙牌移動期間無掉幀
- 記憶體使用保持穩定
- 遊戲過程中CPU使用合理

### 流程10：響應式設計

**目標**：測試不同螢幕尺寸

**步驟**：

1. 在各種瀏覽器視窗大小載入遊戲
2. 測試最小支援解析度
3. 測試超大螢幕
4. 檢查紙牌縮放和間距
5. 驗證UI元素保持可訪問

**預期結果**：

- 遊戲在所有尺寸下都可玩
- 紙牌按比例縮放
- UI元素不重疊
- 文字保持可讀
- 觸控目標足夠大（未來行動支援）

## 除錯技巧

### 常見問題

1. **紙牌無法拖拽**：檢查`isDraggable`屬性是否正確設定
2. **接受無效移動**：驗證`canPlaceOnTableau/Foundation`中的遊戲邏輯
3. **效能問題**：使用React DevTools Profiler識別重新渲染
4. **狀態不持久**：檢查localStorage權限和配額
5. **TypeScript錯誤**：確保所有界面都正確實作

### 瀏覽器開發工具

- 使用React DevTools進行組件檢查
- 效能頁面進行動畫分析
- 應用程式頁面進行localStorage檢查
- 控制台查看錯誤訊息和除錯日誌

### 測試工具

- Jest快照用於組件渲染
- React Testing Library用於用戶互動
- Playwright用於跨瀏覽器測試
- Lighthouse用於效能審計
